# v0.2: connected local studio

Open `http://127.0.0.1:8787/studio` after starting the service. Unlock using `OSA_API_TOKEN` from your private `.local/runtime.env`; the browser keeps it only in tab memory. Never paste it into an issue, chat, screenshot or a public site. Reloading locks the dashboard again.

## Complete a workflow

1. **Research library:** fetch a permitted article or import public English YouTube captions. Fetches are bounded excerpts, not a promise of full-site research. Public web requests enforce robots policy, pin validated public DNS addresses, block private networks, reject unsupported content and stop on page redirects. Search uses your Brave key. Notes in the original product form work without any search account.
2. **Creator shortlist:** search Brave or YouTube with your own key, inspect the evidence and save a candidate. YouTube returns public channel information, not emails. Add a verified contact address and a specific contact basis before marking a creator qualified. Public visibility alone is not consent or a signed partnership.
3. **Product studio:** choose a topic, audience, source and 3-12 chapters. Add sources and creator notes from the library/shortlist. The worker checkpoints every generated section; failed jobs require bounded retries. Review/edit sections before approving a product and immutable price. Revision history is retained. Approved content cannot be edited in place.
4. **Outreach & inbox:** select qualified recipients and create alternating A/B draft variants. Personalization accepts `{name}` and `{niche}`. Review each draft before approving it. Follow-ups wait for a successfully sent initial campaign message. Replies are correlated using both the exact sender and an outgoing Message-ID, never just a subject. Any matching reply stops follow-ups; label interest yourself. Directional variant metrics do not claim statistical significance or silently optimize a live campaign.
5. **Store & orders:** select an approved product; write its headline, description, sample, support address, refund policy and terms. Add/edit/reorder sections, preview, then explicitly publish the page. `/p/SLUG` is the offer, `/p/SLUG/sample` is the sample, and `/p/SLUG/thanks` explains verified delivery. Static page ZIP exports intentionally disable checkout; server-backed pages use configured Razorpay Payment Links. Publishing locally does not create public internet hosting.
6. **Independent adviser:** choose a completed project and ask a question grounded in its evidence. Advice is saved privately. This is not Iman's likeness, private corpus or training.

## Runtime and accounts

Use `pip install -e '.[pdf,research]'` in a project virtual environment for PDF and caption support. Core tests do not need those optional packages. `osa worker` runs generation; `osa mail-worker` independently handles inbox sync, approved mail and approved partner transfers. The Windows supervisor and both Compose files start these separately.

Set keys only in `.local/runtime.env`, then restart the services:

- `BRAVE_API_KEY` for source/creator web search.
- `OSA_YOUTUBE_API_KEY` for official channel discovery.
- `OSA_IMAP_ENABLED=true`, IMAP host/port/user/app-password/folder for your own mailbox. Read-only selection and `BODY.PEEK` preserve read state. Initial sync examines the latest 200 UIDs, at most 50 per cycle; subsequent sync resumes by UIDVALIDITY and UID. Only correlated replies' bodies are retained, capped at 20,000 characters. A mailbox error skips sending for that cycle.
- Existing SMTP variables plus `OSA_MAIL_ENABLED=true` to send approved messages. Confirm your provider's authentication requirements and domain configuration directly.
- Approved Razorpay merchant, matching test keys and a public HTTPS endpoint for payment tests. Live public checkout additionally requires configured email delivery and HTTPS. Complete sandbox payment, duplicate, refund and delivery checks before enabling live mode.

## Partner transfers are not a wallet

Route requires separately approved Razorpay Linked Accounts. A transfer plan derives its amount from an active INR receipt's gross partner share. The operator must verify the recipient account and approve that exact amount. `OSA_ROUTE_ENABLED=true` allows submission using matching test credentials; actual live submission also requires `OSA_LIVE_TRANSFERS=true` and live credentials. These flags default off. Enabling them authorizes submission of already-approved plans.

The worker submits each approved transfer once. Unknown outcomes are marked uncertain and are not retried automatically. A provider response means submitted, not bank-settled. Refunds/disputes cancel unsent plans or flag submitted transfers for reconciliation; reversals and bank reconciliation remain operator/provider actions. Fees, tax, contractual shares and refunds must be accounted for outside the gross accrual. This release does not create financial accounts, hold wallet balances or guarantee redeemable income.

## Public hosting

`compose.production.yaml` and `Caddyfile` provide a conventional host layout: only the TLS proxy exposes ports 80/443; the API and SQLite state stay on the container network. Set `OSA_PUBLIC_HOST` to a domain whose DNS points at your server, `OSA_PUBLIC_URL=https://YOUR-DOMAIN`, and `OSA_OLLAMA_URL` to a model endpoint reachable from the API and worker containers. Set merchant/mail secrets privately. Never expose Ollama directly to the internet.

Start with `docker compose -f compose.production.yaml up --build -d` only after provisioning and reviewing the host. Add host-level firewall rules, backups, monitoring and edge rate limits before taking payments. Caddy handles TLS and body limits; the application has a modest global checkout rate cap, not comprehensive abuse prevention. The built-in Python HTTP server is still an engineering-preview stack, not a hardened multi-tenant SaaS. Docker/TLS deployment has not been exercised on this workstation because Docker is unavailable.

Sites hosting cannot execute this native Python/Ollama/IMAP backend; no disconnected static dashboard is presented as a working online deployment. No public host, merchant account or mailbox has been provisioned automatically.

## Remaining non-equivalence

This is original software spanning the demonstrated workflow categories, not feature-for-feature parity with the paid suite. There is no proprietary lead database, Instagram private-data ingestion, paid swipe-file catalog, Iman persona/training corpus, human coaching, automatic acquisition of partnerships, prerecorded-course video production, advanced drag-and-drop funnel graph editor, statistical campaign optimizer or earnings guarantee. The page editor builds ordered sections and offer/sample/confirmation routes. Human evidence review, editorial quality, legitimate customer acquisition and account onboarding remain essential.
